# 老师快跑 Extras V2：关卡几何与完整流程规范

## 一、V2 重做范围

V2 不在旧版生成器上修补坐标。旧版的“三块地形 + 平均高度 + 固定偏移物件”模型整体废弃，改为：

1. 每个房间先定义玩家实际经过的落脚点序列。
2. 再根据落脚点生成地形、平台、机关和回收路线。
3. 最后把敌人、树、花、告示牌和金币绑定到明确的地表或平台锚点。
4. 写出场景前运行几何验证；存在接缝、浮空、不可达跳跃或镜头外节点时直接停止生成。

旧版十关的主题和总体流程保留，但所有地形与物件坐标重新生成。

## 二、坐标和画面范围

- 单个房间宽度：3,200 像素。
- 每关 10 个房间，总横向范围约 32,000 像素。
- 世界坐标 Y 向下：
  - 高空层：`-620` 至 `-220`
  - 中层：`-180` 至 `120`
  - 地面层：`160` 至 `300`
  - 回收层：`500` 至 `650`
- 普通可玩节点必须处于 `-760 <= y <= 720`。
- DeathPlane 可位于画面外，但不计入普通节点边界检查。
- 相邻房间的出口高度必须与下一房间入口高度完全相等。

## 三、地形规范

### 3.1 地形厚度

- 普通地面厚度：140–190 像素。
- 回收地面厚度：160–210 像素。
- 只有明确标记为墙体的窄地形允许超过 260 像素。
- 墙体宽度限制为 80–180 像素，避免形成大面积空白土块。

### 3.2 房间连接

- 房间出口地形延伸至边界后 16 像素。
- 下一房间入口地形从边界前 16 像素开始。
- 两块连接地形必须同高并重叠 32 像素。
- 禁止 1–95 像素的未标记缝隙。
- 有意设计的跳跃缺口必须：
  - 宽度为 96–220 像素；
  - 两侧有金币、箭头、木桥或平台作为视觉提示；
  - 在路线数据中标记为 `jump`；
  - 下方是可恢复地面或 DeathPlane，不得形成无提示卡死点。

### 3.3 空白控制

- 单块普通地面宽度不得超过 900 像素。
- 宽度超过 620 像素的地面必须至少包含以下两项：
  - 地形起伏；
  - 敌人；
  - 金币路线；
  - 装饰；
  - 可破坏物；
  - 上下层分支入口。
- 画面中不得连续 800 像素只有平地且没有交互。

## 四、可达性规范

每个房间必须提供一条按顺序排列的主路线落脚点：

```text
入口落脚点 → 普通落脚点/机关落点 → 房间出口落脚点
```

生成时对相邻落脚点执行以下检查：

- 普通向前跳：
  - 水平距离不超过 210 像素；
  - 向上高度不超过 90 像素；
  - 向下高度不超过 180 像素。
- 云、木板和蘑菇阶梯：
  - 水平距离不超过 190 像素；
  - 向上高度不超过 82 像素。
- 等待型机关可以放宽到 250 像素，但必须存在安全等待平台。
- 任何超过限制的连接必须拆成更多落脚点。
- 每个房间入口和出口必须属于同一条可达路线。

每条路线同时计算“预计操作时间”：

- 平地移动：按 260 像素/秒估算。
- 普通跳跃：每次增加 0.8 秒。
- 向上平台跳：每次增加 1.15 秒。
- 水中移动：距离按 150 像素/秒估算。
- 枢轴、旋转方块：每组增加 3–6 秒等待预算。
- 回收绕路：按主路线对应部分的 1.25–1.5 倍计算。

每关熟练玩家估算不得低于 180 秒。

## 五、物件锚点规范

所有需要依附地表的物件必须使用：

```text
surfaceId + 横向比例 + 垂直偏移
```

禁止直接使用房间平均高度。

### 5.1 默认垂直偏移

| 物件 | 相对地表偏移 |
| --- | ---: |
| Player 出生点 | -58 |
| 告示牌 | -3 |
| Goomba | -12 |
| Bob-omb | -10 |
| 大树 | -53 |
| 小树 | -38 |
| 花 | -10 |
| 木箱 | -34 |
| FLUDD 箱 | -17 |

### 5.2 锚点验证

- 生成后的物件世界坐标必须与锚点计算结果一致，误差不得超过 2 像素。
- 地面敌人和装饰不得位于地形覆盖范围之外。
- 飞行敌人必须显式标记为 `airborne`，并检查其高度处于镜头范围。
- 水中敌人必须显式标记为 `waterborne`，并处于水域多边形范围内。

## 六、回收路线规范

- 只有存在高空失足风险的房间生成回收层。
- 回收层不贯穿整关，避免成为直线捷径。
- 回收地面由 2–4 块较薄地形组成。
- 回收区出口设置窄墙或高台，阻止继续贴地向右。
- 墙前提供一组经过可达性验证的回升落脚点。
- 回升落脚点最终连接到本房间出口地形。
- 回收路线难度低于主路线，但路程和操作时间更长。

## 七、房间模板

### 7.1 坡地远跑

- 三块连续坡地，中间两处明确跳跃缺口。
- 木桩或木板跨过其中一处。
- 地面敌人全部绑定到坡面锚点。
- 树和花只放在宽度足够的安全区域。

### 7.2 水陆环线

- 入口岸、湖底、出口岸三部分。
- 水面缺口宽 700–1,100 像素。
- 水底拥有连续可游路线，木桥提供上层路线。
- Cheep Cheep 只放在水域内。

### 7.3 爆弹箱门

- 两层地形形成上、下通道。
- 可破坏箱绑定到下层地表。
- 爆弹放在有足够活动空间的地面。
- 出口通过台阶回到目标高度。

### 7.4 蘑菇竖井

- 入口和出口高度差 420–720 像素。
- 每个蘑菇帽的实际顶点进入路线落脚点序列。
- 蘑菇 Stem 的 `position` 表示根部，顶部坐标由 `points` 最后一点计算。
- 不允许把 Stem 根部误当成落脚面。

### 7.5 云端横渡

- 入口高台、6–10 个云落脚点、出口高台。
- 云间距经过统一跳跃限制检查。
- 飞行敌人避开必须落脚的云中心。
- 下方生成局部回收路线。

### 7.6 旋转机关房

- 每组机关前有安全等待地面。
- 机关后有宽度不小于 260 像素的接收平台。
- 不连续堆叠超过两组必须等待的机关。
- 备用静态小平台避免低帧率设备出现必死跳跃。

### 7.7 飞行军团

- 主路线仍由可达云/木板组成，敌人不是落脚点。
- 飞鸟和 Parakoopa 只负责干扰，不承担路线连接。
- 每 600–900 像素提供一个宽安全平台。

### 7.8 控制下降

- 使用左右交错平台限制下降速度。
- 单次向下落差不超过 180 像素。
- 底部接收地面宽度不小于 480 像素。

### 7.9 回收绕路

- 地面较安全，但设置坡墙、箱体或浅水增加路程。
- 末端通过云梯、木板或蘑菇阶梯回到主线。
- 不能从回收层直接触发 FinishWarp。

### 7.10 综合终局

- 组合本关两到三种机制。
- 不引入该关此前未出现的新操作。
- 终点前保留 480–700 像素安全地面。
- FinishWarp 覆盖所有合理抵达高度，但不覆盖回收层未完成区域。

## 九、生成器硬性验收

生成任意一关时，以下任一条件不满足即失败：

- 房间边界存在正数接缝。
- 存在未标记的 1–95 像素地形缺口。
- 存在没有有效地表锚点的地面物件。
- 存在超出普通镜头边界的非 DeathPlane 节点。
- 普通地形厚度超过 210 像素。
- 路线相邻落脚点超过跳跃限制。
- 入口无法沿主路线到达出口。
- 回收路线无法回到主路线。
- FinishWarp 可从未完成的回收层直接触发。
- 预计熟练流程少于 180 秒。

## 十、人工验收

每关至少截取并检查：

1. 房间入口；
2. 最大爬升区；
3. 高空路线；
4. 回收路线；
5. 终点前区域。

第 1、5、10 关必须完整游玩；其余关卡至少从菜单进入并检查三个关键房间。手机尺寸下重复检查第 5 和第 10 关，确认低帧率备用平台和虚拟按键不会造成死路。
