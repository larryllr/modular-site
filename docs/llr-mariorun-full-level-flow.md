# `???` 完整关卡流程设计稿

目标：把主菜单里的 `???` / Extras 做成一整个可持续扩展的关卡流程，而不是一个单段试玩场景。设计参考 `SM63_Godot develop` 的 `sm63_courses` 组织方式：一关不只是地面和终点，而是由背景、前景、地形碰撞、金币路线、敌人节奏、摄像机边界、提示牌、过场/传送点共同组成。

当前实现关卡：

```text
res://scenes/levels/llr_complete/llr_complete_1.tscn
```

真实可提交编辑入口：

```text
tools/patch-llr-complete-level.mjs
```

## 1. 总体方向

关卡名称暂定：

```text
LLR Complete 1：草地训练场 / Grass Training Route
```

设计目标：

```text
1. 不是纯跑酷，要像 SM63 课程一样有探索感和教学节奏。
2. 第一关要能让玩家熟悉移动、跳跃、旋转、敌人、金币、平台、水坑、终点。
3. 移动端优先：不要大量依赖极限小平台，不要要求连续高精度按键。
4. 全流程 3–5 分钟，第一次玩也能通关。
5. 保留后续扩展空间：第二关可以接水域、洞穴、城堡或空中路线。
```

## 2. 参考 `SM63_Godot` 的结构原则

`SM63_Godot` 的 `sm63_courses/1-1.tscn` 类似这样组织：

```text
Course Root
├─ Background / FarBackground
├─ BackGFX
├─ FrontGFX
├─ Collisions
│  ├─ Platforms
│  ├─ BPlatforms
│  └─ Camera Edge
```

我们当前 `Legacy_SM63Redux` 里可直接稳定使用的结构是：

```text
Main
├─ BGT1
├─ CameraArea
├─ Player
├─ Terrain
├─ Items
│  ├─ Signs
│  ├─ Decoration
│  ├─ Coins
│  ├─ Enemies
│  └─ Logs
├─ Water
└─ WarpZone
```

所以落地方式是：不用直接搬 `SM63_Godot` 的课程资源，而是借用它的分层思路，在 `Legacy_SM63Redux` 现有资源内做完整关卡。

## 3. 关卡流程总览

建议把整关分成 8 个段落：

```text
A. 出生安全区：读牌、熟悉移动
B. 基础跳跃区：缓坡 + 低台阶 + 第一组金币
C. 敌人训练区：Goomba + 宽地形，教踩敌/绕开
D. 木桩平台区：连续短平台，训练节奏跳
E. 水坑断桥区：低风险水面 + 三段桥
F. 纵向爬升区：上坡 + 空中平台 + 蓝金币奖励
G. 回落冲刺区：下坡 + 敌人混合 + 金币引导
H. 终点区：最后提示牌 + 传送门回菜单/进入下一关
```

地图长度建议从当前约 `x=4312` 扩到：

```text
x = 0 到 x = 6200
```

这样更像完整一关，而不是短试玩。移动端仍能接受，因为中间有休息点。

## 4. 分段详细设计

### A. 出生安全区：x=0–500

目标：让玩家进入后不会马上失败，能读第一块告示牌。

设计：

```text
Player: Vector2(110, 153)
StartSign: Vector2(190, 178)
地形：平缓，基本不放敌人
装饰：树、花、低坡
金币：3 枚，低空摆放
```

提示牌文字建议：

```text
欢迎来到 ???。这一关会依次练习移动、跳跃、旋转、敌人、水坑和终点传送。
```

### B. 基础跳跃区：x=500–1000

目标：用低台阶引导玩家跳跃。

设计：

```text
一个低台阶 TrainingStep
一段缓坡
一排弧形金币
不放敌人
```

金币摆法：

```text
Vector2(560, 120)
Vector2(610, 105)
Vector2(660, 100)
Vector2(710, 105)
Vector2(760, 120)
```

### C. 敌人训练区：x=1000–1650

目标：第一次遇敌，但不致命。

设计：

```text
宽地形
1–2 个 Goomba
地面金币绕过敌人
一个提示牌说明可以踩/绕开
```

敌人建议：

```text
Goomba1: Vector2(1180, 地面 y)
Goomba2: Vector2(1480, 地面 y)
```

手机端注意：不要把敌人放在坡顶或平台边缘，否则触控玩家容易误伤。

### D. 木桩平台区：x=1650–2300

目标：训练连续短跳，但平台必须宽。

设计：

```text
3–5 个木桩/短平台
金币沿平台中心摆放
下面保留可回收地面或浅水，不要直接深坑死亡
```

当前已有 `Log` 和 `LogFall` 资源，可继续用。

建议：

```text
Log1: x=1750
Log2: x=1820
Log3: x=1890
LogFall: x=2100，用作一次小变化
```

### E. 水坑断桥区：x=2300–3100

目标：引入水面与断桥。

设计：

```text
一个中等宽度 Lake
三块桥平台：左、中、右
水面不做立即死亡，给玩家容错
中间放提示牌
```

提示牌位置必须贴地或贴平台，避免交互不到。

### F. 纵向爬升区：x=3100–4200

目标：关卡中段高潮，给玩家“上升路线”的变化。

设计：

```text
2–4 个空中平台
一条金币弧线引导路线
终点前给一枚蓝金币
```

建议平台：

```text
SkyIsland1: Vector2(3200, 120)
SkyIsland2: Vector2(3500, 85)
SkyIsland3: Vector2(3800, 110)
```

手机端注意：平台宽度不低于 140px，间距不要过大。

### G. 回落冲刺区：x=4200–5400

目标：从高处回到地面，轻微提速，接近终点。

设计：

```text
一个长下坡
2 个 Goomba
金币放成下坡线
装饰密度提高，感觉进入终点段
```

这里可以做成最像正式 SM63 课程的区域：前景装饰、地面高低起伏、敌人和金币混合。

### H. 终点区：x=5400–6200

目标：明确告诉玩家通关，进入传送。

设计：

```text
EndSign
一枚蓝金币或一排金币
WarpZone
```

当前终点是回主菜单：

```gdscript
scene_path = "res://scenes/menus/title/main_menu/main_menu.tscn"
```

后续如果做第二关，可以改成：

```text
res://scenes/levels/llr_complete/llr_complete_2.tscn
```

## 5. 第一阶段落地顺序

不要一次全改完。按下面顺序推进：

```text
Step 1：固定流程蓝图和坐标范围，不改线上玩法
Step 2：扩展地形到 x=6200，先只做完整路面和摄像机范围
Step 3：放置提示牌、金币、敌人，但不加复杂机关
Step 4：加入水坑和木桩平台
Step 5：加入空中平台和蓝金币奖励
Step 6：测试手机端可玩性，微调平台间距和告示牌高度
Step 7：再考虑第二关入口或真正的分关流程
```

## 6. 验收标准

每一步都要满足：

```text
1. 进入 ??? 不黑屏
2. 返回/回场可用
3. PC 键盘可通关
4. 手机触控可通关
5. 告示牌可交互
6. 不出现必须极限跳才能过的点
7. npm run predeploy 成功
8. npm test 通过
```
