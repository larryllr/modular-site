# 分页面每日自动背景设计

## 目标

为每个分页面增加独立的“每日自动背景”开关。开启后，页面每天使用 Bing 首页风景图作为背景；背景应在页面内容显示前完成加载和解码，避免先出现白底再闪入图片。

## 管理与数据

- 在分页面设置中增加“每日自动背景”开关。
- `SitePage` 增加布尔字段 `dailyBackgroundEnabled`，默认值为 `false`。
- 只在 KV 配置中保存开关，不保存远程图片或每日 URL。
- 服务端和浏览器端都对旧配置补全默认值，保证已部署内容继续可用。
- 开启自动背景时，每日图片优先于手动 `backgroundImage`；自动背景不可用时回退到手动背景。

## 图片来源与代理

- Worker 使用 Bing `HPImageArchive.aspx` 获取当天图片元数据。
- 优先根据 `urlbase` 请求 UHD 图片；UHD 不可用时回退接口返回的 1920×1080 图片。
- 浏览器只访问本站的每日背景端点，不直接请求 Bing，避免跨域差异并集中处理缓存和回退。
- Worker 校验 Bing 返回的相对图片路径，只允许 `https://www.bing.com/` 来源，防止开放代理。
- 每日图片响应使用边缘缓存；缓存时间应允许当天复用，同时不会长期固定在旧图片。

## 页面加载

- 启动时先加载站点配置并判断当前路由对应页面是否开启自动背景。
- 若开启，预加载本站每日背景端点，并使用 `HTMLImageElement.decode()` 等待解码完成。
- 解码成功后再渲染页面，并把已准备好的每日背景 URL 交给现有 `applyPageBackground()`。
- 等待期间使用深青色加载底色，不显示空白页面。
- 设置有限等待时间；超时、网络失败或解码失败时立即回退到手动背景并继续渲染，不能阻塞页面。
- 管理员预览显示自动背景已开启的状态，但不因远程图片加载阻塞后台编辑。

## 视觉与现有改动

- 保留已确认但尚未发布的清晰浅青背景、白色标题、90% 半透明卡片和等宽等高网格。
- 普通手动背景和每日自动背景使用同一套背景图层与卡片样式。
- 没有任何可用背景时，页面维持现有白色样式。

## 错误处理

- Bing 元数据请求失败、JSON 无效、图片 URL 无效或图片请求失败时，端点返回明确错误状态。
- 前端不向访客显示技术错误；自动使用手动背景或无背景页面。
- 每日背景故障不影响页面配置、模块、评论或管理员功能。

## 验证

- 服务端测试覆盖字段规范化、每日端点来源限制、UHD 优先和 1920 回退。
- 前端测试覆盖管理开关、旧配置兼容、自动背景优先、失败回退和解码前不显示页面。
- 运行前端语法、TypeScript、完整测试和差异格式检查。
- 在桌面与手机视口验证正式分页面：背景无白闪、模块等宽等高、失败回退可用。
- 完成后部署 Cloudflare、记录 Version ID、更新交接文件并通过本机 `10808` 代理推送 GitHub。

## 已接受限制

Bing 首页图片接口不是正式公开 API，返回元数据也可能提示部分图片仅限桌面壁纸。用户已明确选择该来源并接受接口稳定性与图片授权风险。
