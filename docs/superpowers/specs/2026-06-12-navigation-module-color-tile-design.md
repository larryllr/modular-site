# 导航模块彩色磁贴设计

## 目标

在每个导航模块顶部增加一块整宽、鲜艳的长方形装饰磁贴，让多个导航模块更容易区分，同时保持标题和网址列表清晰。

## 视觉结构

- 磁贴位于导航模块内容最顶部、标题上方。
- 磁贴不显示图标、文字或网站数量，只承担装饰作用。
- 磁贴占满模块内容宽度，高度约 `34px`，使用与现有卡片一致的小圆角。
- 磁贴使用鲜艳的双颜色渐变和轻微彩色阴影。
- 标题继续单独显示在磁贴下方。
- 网址条目中的自动 favicon 保持不变。

## 配色

- 内置多组鲜艳渐变，例如紫蓝、粉橙、青绿和红紫。
- 根据导航模块 `id` 计算稳定色号，同一个模块每次加载保持相同配色。
- 不增加管理员配色字段，避免扩大配置结构和旧数据兼容范围。

## 响应式

- 单导航模块全屏模式和多模块卡片模式都显示磁贴。
- 手机端仍为整宽磁贴，高度略微缩小，避免占用过多阅读空间。

## 实现范围

- `public/app.js`：为导航模块计算稳定的配色类并渲染空装饰元素。
- `public/styles.css`：定义磁贴尺寸、渐变配色、阴影和手机端样式。
- 不修改 Worker 数据结构、管理员编辑表单或 Cloudflare KV 配置。

## 验证

- 源码断言确认导航模块包含装饰元素和稳定配色函数。
- 确认装饰元素没有文字内容。
- 执行 JavaScript 语法检查、TypeScript 检查和 `git diff --check`。
- 部署后记录 Cloudflare Version ID，并通过 `10808` 代理推送 GitHub。

## 同批性能优化：增量保存

### 当前问题

- 站点配置当前约 `3.15 MiB`，包含 Base64 图片和博客富文本。
- 管理员每次保存都会上传完整配置。
- Worker 清洗并覆盖写入完整 KV 值后，又在响应中返回完整配置。
- 因此一次保存会同时产生约一份完整上传和一份完整下载。

### 补丁协议

- 前端在加载或成功保存后保留一份基准配置。
- 保存时比较基准配置与当前配置，生成受限 JSON Patch 操作。
- 普通字段使用 `replace`；对象增删使用 `add` 和 `remove`；带 `id` 的数组排序使用 `move`。
- 页面、模块、文章和导航网址等带 `id` 的对象数组按 ID 比较，避免修改一个字段时上传整个数组。
- 标签、分类和导航顺序等小型标量数组可以整体替换。
- 请求包含 `baseUpdatedAt`。Worker 发现远程版本已变化时返回 `409`，防止多标签页静默覆盖。

### Worker 处理

- 新增 `/api/admin/config-patch`，沿用管理员鉴权。
- 限制补丁操作类型、数量、路径深度，请求体应用层上限为 `100 MB`。
- Worker 从 KV 读取当前配置，校验版本后应用补丁。
- 应用补丁后的配置继续经过 `normalizeSiteConfig()`。
- limited 管理员继续经过 `mergeLimitedConfig()`，现有页面、模块和文章锁定规则不变。
- KV 仍整值写入，因为单个 KV key 不支持局部写入。
- 成功响应只返回 `ok`、`role` 和新的 `updatedAt`，不再回传完整配置。

### 客户端行为

- 管理后台保存优先调用补丁接口。
- 没有变化时不发请求，直接显示“没有需要保存的修改”。
- `409` 时提示配置已在其他页面更新，要求重新加载后再编辑。
- 补丁接口不可用时回退到现有整包保存接口，保持部署过程和旧 Worker 兼容。
- 快速发布、文章编辑、删除和排序统一使用同一增量保存帮助函数。

### 范围约束

- 本轮不改造撤销栈。撤销栈仍保存完整配置快照，后续可单独优化内存占用。
- 本轮不迁移 Base64 图片到 R2。
